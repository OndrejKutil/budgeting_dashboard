## 2. Decisions and deviations from the spec

| Topic | Decision | Deviation? |
|---|---|---|
| Rounds | Four phone rounds (A–D) instead of six phases, to cut phone testing | Yes: phases 1+2 → A, 3+4 → B, 5a → C, 5b+6 → D. Each round still ends with an install-and-test gate. |
| OAuth in the app | GitHub **and Google** sign-in run in `ASWebAuthenticationSession` (the iOS sign-in sheet) and return to the app through `<bundle-id>://auth/callback` | Yes: the spec disabled Google in the app. With the sheet, Google is allowed, passkeys work, and third-party pages never load in the app's web view. `server.allowNavigation` stays empty. |
| Signing in CI | Built unsigned, then **ad-hoc signed** (`codesign -s -`) with the entitlements embedded | Yes (spec: "unsigned"). SideStore reads App Groups from the binary's entitlements. Without them, the App Group is never registered. |
| Background refresh of widget data | **None.** The widget updates whenever the app is open. | Narrows the spec's "possible". Supabase refresh tokens rotate, so a native background refresh would compete with the web view's token and could end the session. |
| Face ID lock | Native (Swift `LocalAuthentication`), not a web overlay. It also covers the app-switcher snapshot. | Spec left it open. The plugin route would show content before the lock. |
| Native ↔ web bridge | One app-local Capacitor plugin, `BudgetNative` (auth sheet, lock settings, widget data, App Group info, profile expiry), plus `@capacitor/local-notifications` | Implementer's call per spec |
| Project layout | `src/mobile/` (own `package.json`, `capacitor.config.ts`, `project.yml`, Swift sources, offline page). The `.xcodeproj` is generated by XcodeGen in CI and never committed. | Implementer's call per spec |
| iOS workflow | New `.github/workflows/ios.yml`. Triggers: push touching `src/mobile/**` or the workflow itself, plus `workflow_dispatch`. `ci.yml` unchanged. | — |
| Web changes | In `src/frontend`, gated on `Capacitor.isNativePlatform()`. Browsers and the PWA keep their current behaviour. | — |
| Update channel | Releases built from `main` only, each a GitHub Release with the `.ipa`. `source.json` lives at a fixed URL (a release asset on a fixed tag, or a dedicated branch; decided in round B). Build number = `github.run_number`. | — |
| Versions | Re-checked in round 0 against current docs, not taken from the spec | — |

  because the app loads production. Every round's PR is merged before its phone test.

### Round A: shell, CI, login (≈4–5 h / 5–7 h)

Build:
1. `src/mobile/`: Capacitor iOS project, `server.url = https://budget.ondrejkutil.com`,
   `server.errorPath` → bundled offline page, `project.yml` (app target only for now),
   status bar and keyboard settings. No `WKAppBoundDomains`.
2. `ios.yml`: install, `cap sync`, `xcodegen`, `xcodebuild archive` (unsigned), ad-hoc

   smoke-test job. A check that Capacitor plugin versions match between `src/mobile` and
   `src/frontend`.
3. `BudgetNative.startAuthSession(url)`: the `ASWebAuthenticationSession` wrapper.
4. Backend `login.py`: `/oauth/github` and `/oauth/google` accept `client=ios`, which

5. Frontend: add `@capacitor/core`; in the native app, `LoginPage` gets the URL with
   `client=ios`, opens the sheet and hands the returned fragment to the existing

6. Docs: `docs/mobile/README.md` (layout, build, decisions) and the **phone setup**

| Item | Result |
|---|---|
| Repository | Public, so macOS runner minutes are free |
| Capacitor | 8.6.2 (`@capacitor/core`, `ios`, `cli`), SPM by default, iOS 15.0 minimum, needs Xcode 26+. `cap add`/`cap copy` work on Linux; `cap sync`/`cap update` need an existing `project.pbxproj` (it exits 0 with a stale `Package.swift` otherwise). |
| `@capacitor/local-notifications` | 8.3.1 (round B) |
| Runners | `macos-26` (= `macos-latest`), Xcode 26.6 default, iOS 26.2–26.5 simulators (iPhone 17 family). `macos-15` defaults to Xcode 16.4, too old. XcodeGen not preinstalled: `brew install xcodegen` (2.48.0). Don't use XcodeGen's new `xcproj` format. |
| App-local plugin | `CAPPlugin, CAPBridgedPlugin` + `bridge?.registerPluginInstance` in a `CAPBridgeViewController` subclass. The 8.5+ template builds the root view controller in `SceneDelegate`, so the subclass is set there. |
| SideStore | Latest release 0.7.0-alpha (15 Sep 2026); nightly 27 Oct 2026. App Groups are read from the **entitlements embedded in each binary** (app and each `.appex`); without them no group is registered and the group entitlement is stripped. Group rename: `group.X` → `group.X.<TEAMID>`. 0.7.0-alpha writes `ALTAppGroups` into Info.plist; nightly no longer does (reads the signature instead), so the app must fall back to its own entitlements / `embedded.mobileprovision`. |
| SideStore updates | Source JSON per AltStore format (`version`, `buildVersion`, `date`, `downloadURL`, `size` required per version). SideStore compares `version` as strict `X.Y.Z` semver; a change in `buildVersion` alone is ignored. Hence `1.0.<run number>`. The IPA's `CFBundleShortVersionString`/`CFBundleVersion` must equal `version`/`buildVersion`. |
| SideStore on iOS 26.6.x | Sign-in failures (HTTP 503) were fixed in Sep but reappeared 20–22 Nov 2026 (issue #1744, discussion #1741), no maintainer-confirmed fix yet; workarounds involve the anisette server settings. |
| OAuth sheet | Google's iOS SDK itself uses `ASWebAuthenticationSession`; no reports of Google blocking it. Supabase allows custom-scheme redirect URLs; implicit flow returns tokens in the fragment of the 302; an unlisted `redirect_to` silently falls back to the Site URL. `init(url:callback:.customScheme)` on iOS 17.4+, the older initializer below. No Info.plist URL type or entitlement needed. |

## 8. Risks

- SideStore breaks after an Apple change: the app keeps running until its profile expires
  (≤7 days); the PWA is the fallback.
- Each native fix costs one CI run (~10 min); there is no local Swift compiler. The
  simulator smoke test catches launch failures before the phone does.
- Google could start rejecting the sign-in sheet in future. The fallback is disabling the
  Google button in the app, as the original spec planned.
