# Budget iOS app (native shell)

A thin native iOS app around https://budget.ondrejkutil.com, built with Capacitor, compiled in
GitHub Actions (no Mac) and installed with SideStore on a free Apple ID.

- Plan and decisions: [docs/specs/ios-app-plan.md](../specs/ios-app-plan.md)
- Phone setup for the owner: [setup-guide.md](setup-guide.md)

## How it works

The app is a WKWebView that loads the live site (`server.url` in `src/mobile/capacitor.config.json`).
A site deploy reaches the app the next time it opens; only native changes need a new build.

Native features are exposed to the web app through one app-local Capacitor plugin,
`BudgetNative`:

| Side | File |
|---|---|
| Swift | `src/mobile/ios/App/App/BudgetNativePlugin.swift` (registered in `BudgetBridgeViewController.swift`) |
| TypeScript | `src/frontend/src/lib/native/budgetNative.ts` |

Web code checks `isNativeApp()` before using anything native, so browsers and the PWA behave as
before.

| Feature | Native side | Web side |
|---|---|---|
| Face ID lock + app-switcher cover | `PrivacyLock.swift` (scene lifecycle, `LocalAuthentication`) | Profile › App (settings only) |
| Page zoom (Safari's 85 % equivalent) | `BudgetBridgeViewController.applyPageZoom` (`WKWebView.pageZoom`) | Profile › App |
| Settings storage | `AppSettings.swift` (UserDefaults; read before the site loads) | `getAppSettings` / `setAppSettings` |
| Local notifications | `@capacitor/local-notifications` | `lib/native/notifications.ts`, synced by `components/native/NativeNotificationSync.tsx` |
| Status bar style | `setStatusBarStyle` | `components/native/NativeStatusBar.tsx` |
| Expiry banner | `ProvisioningInfo.swift` (`embedded.mobileprovision`) | `components/native/NativeExpiryBanner.tsx` |
| Widgets + controls | `BudgetWidget/BudgetWidget.swift` (extension), `Shared/WidgetSnapshot.swift` | `lib/native/widgets.ts`, `lib/native/data.ts` |
| Deep links (`com.ondrejkutil.budget://add`, `import-screenshot`, `open?path=`) | `SceneDelegate` → `BudgetNative` `deepLink` event | `components/native/NativeDeepLinks.tsx` |
| App Group lookup | `Shared/AppGroup.swift` (`ALTAppGroups` → profile → declared) | — |

`components/native/NativeSync.tsx` loads the data once (`lib/native/data.ts`) and refreshes both
the notifications and the widget snapshot on login, on returning to the foreground, after any
successful save (react-query mutation) and on a settings change; it clears both on logout.

- Notifications: 20:00 daily reminder for the next 7 days (today's skipped once a transaction is
  dated today) and 07:00 "due today" for each active recurring payment's next date (the Pi
  auto-posts at 05:00). Preferences live in `localStorage`.
- Widgets: a JSON `WidgetSnapshot` (this month's summary, upcoming payments, localized labels)
  stored in the App Group; the widget timelines add an entry at each midnight so days-left and
  per-day stay current without the app. No budgets are used.
- The App Group's real name is `group.com.ondrejkutil.budget.<TEAMID>` after SideStore signs it;
  both targets resolve it at runtime.

### Sign-in with GitHub/Google in the app

Google blocks OAuth inside embedded web views, so the app runs OAuth in the iOS sign-in sheet
(`ASWebAuthenticationSession`):

1. `src/frontend/src/lib/oauth.ts` asks the backend for the URL with `?client=ios`.
2. The backend (`src/backend/routers/login.py`) sets Supabase's `redirect_to` to the fixed
   `com.ondrejkutil.budget://auth/callback`. Without `client=ios` it's the website, as before.
3. `BudgetNative.startAuthSession` opens the sheet; when Supabase redirects to the custom scheme
   the sheet closes and returns the URL. The tokens are in its fragment.
4. The web app hands the fragment to the existing `/auth/callback` page.

`com.ondrejkutil.budget://auth/callback` must be in Supabase → Authentication → URL Configuration →
Redirect URLs. If it isn't, Supabase silently falls back to the Site URL and the sheet never closes.

Account linking (profile page) is hidden in the app; it works on the website.

## Layout

```
src/mobile/
  package.json            Capacitor CLI + iOS runtime (exact versions; must match src/frontend)
  capacitor.config.json   appId, server.url, errorPath, iOS options
  www/                    bundled pages: offline.html (shown when the site can't load)
  scripts/check-versions.mjs
  ios/App/project.yml     XcodeGen spec — the source of truth for the Xcode project
  ios/App/App/            Swift sources, Info.plist, App.entitlements, assets
  ios/App/CapApp-SPM/     Swift package Capacitor manages (Package.swift is regenerated by `cap sync`)
```

`App.xcodeproj` is generated in CI and never committed.

## Build (CI)

`.github/workflows/ios.yml` runs on pushes that touch `src/mobile/**` or the workflow itself, and
manually ("Run workflow", available once the workflow is on `main`). It never runs for site-only
changes.

Steps, in this order (each depends on the previous one):

1. `npm ci`, then `scripts/check-versions.mjs`.
2. `npx cap copy ios` — copies `www/` to `ios/App/App/public` and writes `capacitor.config.json`.
3. `xcodegen generate` in `ios/App`.
4. `npx cap update ios` — rewrites `Package.swift` (it reads the deployment target from the
   generated project). CI fails if the result differs from the committed file.
5. `xcodebuild archive` without signing, then **ad-hoc signing** (frameworks → extensions → app)
   with the entitlements files. SideStore decides App Groups and capabilities from the entitlements
   embedded in each binary, so an unsigned build would lose them.
6. The `.ipa` is uploaded as an artifact (`Budget-1.0.<run>-ipa`).
7. A Debug build is launched on an iPhone simulator; CI fails if it crashes, and prints a small
   screenshot (base64 JPEG between `SCREENSHOT_BASE64_BEGIN/END`) plus the app log.

Version: `1.0.<run number>`, build number `<run number>`. SideStore compares versions as strict
`X.Y.Z`, so the patch number must keep increasing.

8. **Builds from `main` only:** a GitHub Release `ios-v1.0.<run>` with the `.ipa`, and
   `scripts/make-source.py` rewrites the SideStore source, uploaded to the `ios-source`
   release at a fixed URL:
   `https://github.com/OndrejKutil/budgeting_dashboard/releases/download/ios-source/source.json`.
   SideStore shows the new version as an update.

## Adding a Capacitor plugin

1. `npm install --save-exact @capacitor/<name>@<version>` in **both** `src/mobile` and `src/frontend`.
2. In `src/mobile`, regenerate `Package.swift`: CI does it, but the committed file must match; the
   simplest way is to copy the `Package.swift` CI prints in the failing step, or run `npx cap sync ios`
   on any machine with a generated project.
3. Web changes ship with the site deploy; the native part needs an app build and update.

## Rules

- No `WKAppBoundDomains`: it breaks Capacitor's bridge.
- Don't change the bundle ID (`com.ondrejkutil.budget`) — it would burn App IDs and lose app data.
- At most one app extension (`BudgetWidget`, which holds every widget and control); each
  extension uses one of the 10 weekly App IDs.
- Never hardcode the final App Group name: SideStore appends `.<TEAMID>` at signing.
